2026년 대한민국 급여 실수령액 계산기
====================================

1. 프로젝트 소개
----------------
이 프로젝트는 당월 기준 세전 연봉 또는 월 총급여, 월 비과세액, 공제대상가족 수, 8~20세 자녀 수를 입력해 예상 월 실수령액과 공제 상세내역을 계산하는 정적 웹사이트입니다. 목표 월 실수령액으로 필요한 연봉을 역산하는 기능도 제공합니다. 기본 계산 입력은 연봉이며, 연봉을 12개월 균등 지급으로 환산합니다. 월급 입력도 선택할 수 있고, 원천징수 비율은 100%로 고정합니다.

정적 웹사이트란 별도 서버 프로그램 없이 HTML, CSS, JavaScript 파일을 브라우저에서 실행하는 형태를 말합니다. 급여 입력값은 브라우저에서 계산하며 이 프로젝트 코드에는 입력값을 서버로 전송하거나 저장하는 기능이 없습니다.

계산 결과는 참고용 추정치입니다. 회사의 신고 보수월액, 보수 구성, 비과세 항목, 정산, 상여 및 법령 변경 등에 따라 실제 급여명세서와 다를 수 있습니다.

3. 실행 방법
------------
1) ZIP 파일을 압축 해제합니다.
2) index.html을 열어 첫 화면을 확인할 수 있습니다. 브라우저 보안 정책에 따라 file:// 경로에서는 JavaScript 데이터 파일을 정상적으로 불러오지 못할 수 있으므로, 전체 계산 기능은 로컬 정적 서버 또는 Vercel 미리보기에서 확인하는 것을 권장합니다.
3) GitHub Pages, Vercel 등 정적 호스팅에 프로젝트 폴더 안의 파일과 폴더를 그대로 배포합니다. salary 폴더만 따로 올리지 말고 index.html, assets, data, salary 폴더를 함께 유지합니다.

4. Config 설정, 공개 안내 문구 및 고급 직접입력 ON/OFF
--------------------------------------------------
data/app-config.js 파일의 features.enableAdvancedInsuranceInput 설정을 변경합니다.

- false: 기본값이며 고급 직접입력 기능을 끕니다. 자동 계산만 사용합니다.
- true: 국민연금 기준소득월액과 건강보험 보수월액의 자동/직접입력 선택 기능을 표시합니다.
- 값은 따옴표 없는 불리언 true 또는 false를 사용합니다. 문자열 "true" 또는 "false"를 사용하지 마세요.
- 일반 사용자 화면에는 운영 Config를 변경하는 메뉴가 없습니다. 설정 변경은 소스 파일 수정 및 재배포로 적용합니다.
- OFF 상태에서는 숨겨진 직접입력값이 계산에 반영되지 않습니다. 자동 모드로 바꾸면 해당 직접입력값은 비워집니다.
- 국민연금 직접입력은 적용월의 기준소득월액 상·하한을 검증합니다. 건강보험 직접입력은 코드에 설정된 입력 허용 범위를 검증합니다.

계산기 화면의 공개 안내 문구는 같은 파일의 `display` 설정에서 수정합니다.

- 원천징수 안내 문구는 `display.fixedWithholdingNotice`의 문장을 바꿉니다.
- 하단 문구는 `display.publicGuidance.sections`에서 원하는 `text`를 수정합니다.
- 한 줄만 숨기려면 해당 항목의 `visible`을 `false`로 바꿉니다. 다시 표시하려면 `true`로 바꿉니다.
- 섹션 전체는 그 섹션의 `visible`로, 안내 영역 전체는 `publicGuidance.visible`로 표시 여부를 바꿉니다.
- 계산·테스트용 운영 메모는 공개 안내 설정에 넣지 않습니다. 일반 사용자가 보는 문구와 분리해 관리합니다.

급여 입력 방식
--------------
- 계산 기능은 상단의 `실수령액`과 `연봉 역산` 선택으로 구분합니다. 목표 월 실수령액은 `연봉 역산`에서만 입력합니다.
- `실수령액`에서 연봉을 선택하면 퇴직금 드롭다운이 나타납니다. 별도이면 연봉÷12, 포함이면 연봉÷13으로 월급여를 추정합니다. 퇴직금 포함 방식은 단순 환산이며 법정 퇴직금 산정액을 계산하지 않습니다.
- 급여 입력 방식은 드롭다운으로 연봉/월급 중 선택합니다. 월급을 선택하면 입력 항목은 `월급여(원)`으로 표시하고 퇴직금 드롭다운을 숨깁니다. 목표 월 실수령액은 `연봉 역산`에서만 입력합니다.
- 적용월은 화면에서 선택하지 않습니다. 브라우저의 한국 시간 기준 당월을 사용하고, 화면에 계산 기준 월을 안내합니다. 매니페스트에 등록된 과거 연도 자료는 보존하되 일반 화면에서 과거 월 조회는 제공하지 않습니다.
- 매니페스트의 `defaultHistoryYears: 10`은 조회 기본 범위 설정값일 뿐 10개 연도의 데이터 보유를 뜻하지 않습니다. 현재 매니페스트에는 2026년 기준만 등록되어 있습니다.
- 계산기 기본 입력은 세전 연봉이며, 연봉을 12개월 균등 지급하는 것으로 보고 월 급여로 환산합니다. 원 미만은 버립니다.
- 월 비과세액은 연봉/월급 입력 방식과 관계없이 월 금액으로 입력합니다.
- 상여금·성과급·퇴직금 포함 여부에 따라 실제 월별 급여명세서와 차이가 생길 수 있습니다. 현재 연봉 입력은 별도 지급을 모델링하지 않습니다.
- 월 급여 입력은 급여 입력 방식에서 `월급`을 선택해 사용할 수 있습니다.
- 원천징수 비율은 화면에서 입력하지 않으며 100% 기준으로 계산합니다. 회사가 80% 또는 120%를 적용하거나 급여명세서 조건이 다르면 실제 월 실수령액과 차이가 날 수 있습니다.
- `연봉 역산`을 선택하면 목표 월 실수령액에 도달하는 최소 월 총급여를 이분 탐색으로 찾고, 이를 12개월 균등 지급 연봉으로 환산합니다. 가족 수, 비과세액, 당월 및 선택된 고급 보험료 기준은 일반 계산과 동일하게 반영합니다.
- 역산은 월 총급여 10억 원까지의 계산 범위에서 처리합니다. 이 범위에서 목표액을 만들 수 없으면 범위 초과 안내를 표시합니다.

5. 연도별 세액표 추가
--------------------
새 연도 자료는 공식 원본을 확보하고 적용 기간을 확인한 뒤에만 추가합니다. 2027년 이후 세율이나 세액표는 미리 추정하거나 임의 생성하지 않습니다.

1) 공식 근로소득 간이세액표 원본을 확보합니다.
2) data/income-tax-YYYY.js 파일을 만들고 급여 구간과 가족 수별 세액을 원본과 비교합니다. 구간 사이를 임의로 보간하지 않습니다.
3) data/tax-table-manifest.js의 tables 목록에 적용 시작일(from), 종료일(to), 파일 경로(src), 데이터 식별자(id), 전역 변수명(globalName), 연도(year)를 등록합니다.
4) 같은 연도 중간에 세액표가 바뀌면 서로 겹치지 않는 적용 기간과 구분되는 데이터 식별자/전역 변수명을 사용합니다.
5) 테스트를 실행하고 해당 기간의 대표값, 경계값, 가족 수 열 전체를 검증합니다.
6) 데이터가 없는 적용 기간은 등록하지 않습니다. 다른 연도의 데이터를 대신 사용하지 않습니다.

6. 연도별 보험료 규칙 추가
-------------------------
1) 공식 기관 자료와 시행일을 확인합니다.
2) data/payroll-rules-YYYY.js에 연도별 요율, 상·하한, 끝수 처리, 적용 기간을 등록합니다. 요율은 소수로 저장하고 주석에 백분율도 적습니다. 예: 4.75%는 0.0475입니다.
3) data/tax-table-manifest.js의 rules 목록에 적용 시작일/종료일, 파일 경로, 전역 변수명 및 데이터 식별자를 등록합니다.
4) 연도 중 법령이 변경되면 시행일을 기준으로 기간을 나누고, 기간별 규칙을 명확히 구분합니다.
5) salary/calculator.js의 계산 엔진이 해당 규칙 구조를 지원하는지 확인하고, 회귀 테스트 및 경계값 테스트를 추가합니다.
6) 공식 자료가 확인되지 않은 값은 등록하지 않습니다. 기존 연도 데이터를 덮어쓰지 말고 보존합니다.

7. 자동 테스트 실행 방법
-----------------------
테스트는 Node.js가 설치된 컴퓨터에서 실행할 수 있습니다. Node.js는 JavaScript 테스트를 컴퓨터에서 실행하는 도구입니다.

Windows 명령 프롬프트 또는 터미널에서 압축 해제한 프로젝트 루트 폴더(index.html이 있는 폴더)로 이동한 다음 실행합니다. Node.js는 JavaScript 테스트를 실행하는 프로그램입니다.

  node tests/run-all-tests.js

위 명령은 테스트 파일을 올바른 작업 폴더에서 순서대로 실행하고 테스트 묶음별 통과·실패·미실행 건수를 출력합니다. 개별 테스트만 실행하려면 다음 명령을 사용합니다.

  cd tests
  node test-calculator.js
  node test-operations.js
  node test-full-audit.js

프로젝트 루트에서 개별 파일을 직접 실행하면 상대 경로가 맞지 않아 실패할 수 있으므로, 가능하면 통합 실행기 `node tests/run-all-tests.js`를 사용하세요. `test-calculator.js`는 계산 엔진·회귀·데이터 로딩을, `test-operations.js`는 SEO 메타데이터·Config·운영 계약을, `test-full-audit.js`는 세액표 전체 구간 경계·입력 조합·보험료 경계·역산 최소 조건을 확인합니다.

자동 테스트는 실제 PC/스마트폰 브라우저 화면이나 실제 Vercel 네트워크 환경을 대신하지 않습니다. 실행하지 않은 브라우저 테스트를 통과로 표시하지 마세요. 테스트 코드를 작성했다는 사실과 실제 실행 결과를 구분하고, 실행 결과는 `TEST-REPORT.txt`에 기록합니다.

8. GitHub 및 Vercel 배포 방법
-----------------------------
1) 배포 전 현재 운영 파일과 ZIP 백업을 별도로 보관합니다.
2) ZIP을 압축 해제합니다.
3) GitHub 저장소에 프로젝트 폴더 내부의 파일과 폴더를 업로드합니다. ZIP 파일 자체만 업로드하면 웹사이트가 실행되지 않습니다.
4) index.html, assets, data, salary, tests가 프로젝트 루트에 있는지 확인합니다. 프로젝트 폴더를 한 단계 더 중첩해 업로드하지 마세요.
5) Vercel에서 해당 GitHub 저장소를 Import하고 정적 사이트로 배포합니다. 프레임워크가 없는 프로젝트이므로 기존 배포 설정을 유지합니다.
6) 배포 미리보기에서 첫 화면, 계산기 링크, 대표 급여 계산, 오류 메시지, 모바일 화면, 세액표 로딩을 확인합니다.
7) 확인을 마친 뒤에만 운영 배포를 진행합니다. 이 README 작성 시점에는 이 ZIP을 실제 Vercel에 배포하지 않았습니다.

9. SEO 및 블로그/워드프레스 링크
-------------------------------
- 사이트 루트 URL은 첫 화면(index.html), 계산기 URL은 /salary/ 경로를 사용합니다.
- 현재 배포 주소 기준으로 루트 페이지와 계산기 페이지에 title, description, viewport, robots, Open Graph 메타데이터 및 canonical URL을 설정했습니다. 같은 페이지에서 title, description, viewport, canonical이 중복되지 않도록 관리합니다.
- canonical은 검색엔진에 대표 URL을 알려주는 메타데이터입니다. 현재 주소가 바뀌거나 독립 도메인을 연결하면 index.html과 salary/index.html의 canonical 및 og:url을 실제 공개 URL로 수정합니다. 확인되지 않은 도메인을 임의로 입력하지 마세요.
- 네이버 블로그와 워드프레스에서는 https://2026-pay-calculator.vercel.app/salary/ 링크로 계산기를 열 수 있습니다. 워드프레스 페이지를 만들거나 iframe을 삽입할 필요는 없습니다.
- 이 프로젝트에는 iframe, 애드센스 코드, 실제 광고 영역이 포함되어 있지 않습니다. 추후 다른 계산기를 추가할 때는 각 계산기의 독립 URL과 데이터/계산 엔진을 분리하는 방향을 권장합니다.

10. 주요 오류 확인 방법
----------------------
- 세액표 또는 보험료 기준을 불러오지 못했다는 메시지: URL 경로, 파일명 대소문자, 매니페스트의 src/globalName, GitHub 업로드 누락 여부를 확인합니다. 네트워크를 복구한 뒤 다시 계산하여 재시도합니다.
- 현재 월의 기준이 등록되어 있지 않다는 메시지: data/tax-table-manifest.js에 현재 날짜를 포함하는 세액표와 보험료 규칙이 모두 등록되어 있는지 확인합니다. 자료가 없으면 다른 연도 데이터를 임의로 연결하지 않습니다.
- 고급 입력란이 보이지 않음: data/app-config.js의 enableAdvancedInsuranceInput이 불리언 true인지 확인하고, 파일 수정 후 배포가 갱신되었는지 확인합니다.
- 테스트 실패: 오류 메시지와 테스트 이름을 확인합니다. 원인을 수정한 뒤 프로젝트 루트에서 `node tests/run-all-tests.js`, `e2e` 폴더에서 Playwright 테스트를 다시 실행합니다.
- 화면 스타일이 깨짐: assets/css/common.css 경로와 대소문자, 프로젝트 루트 폴더 구조를 확인합니다.

13. 자동 테스트 및 Codex 활용 기준
---------------------------------
- Codex는 필수 도구가 아닙니다. 기존 Node.js 개발 환경에서 테스트를 실행할 수 있으며, Codex 사용 가능 여부와 무관하게 작업을 진행합니다.
- 권장 실행 명령: 프로젝트 루트에서 `node tests/run-all-tests.js`
- 실행기는 테스트 파일 2개를 각각 실행하고 통과/실패/미실행 테스트 묶음 수를 표시합니다. 개별 assert 수가 아니라 테스트 파일(테스트 묶음) 단위 집계입니다.
- 실제 브라우저, 스마트폰, 모바일 키보드, 실제 네트워크 장애/복구 및 Vercel 배포 테스트는 별도 환경이 필요합니다. 실행하지 않은 항목은 미실행/미검증으로 기록합니다.
- 자동 테스트가 통과하더라도 보험료 요율·상하한·법정 끝수 처리 등 공식 자료와 전수 대조하지 않은 계산 기준은 미검증으로 봅니다. 자세한 실행 결과는 `TEST-REPORT.txt`를 확인하세요.
